# Meerkat Fugue documentation

Meerkat Fugue is a Rust service that turns a Linear project into a safe,
observable coding-agent queue. It polls eligible Linear issues, prepares an
isolated workspace for each issue, launches the configured native Meerkat mob,
and records human-readable handoff evidence in Linear and GitHub.

## Core concepts

### Linear is the intake and handoff surface

Fugue reads Linear issues from configured project lanes. Workers keep exactly
one persistent comment headed `## Fugue Workpad` with the plan, progress,
validation, and PR or handoff evidence.

### Workspaces are isolated by issue

Each issue receives a deterministic directory under `workspace.root`. Hooks run
inside that directory, so operators decide how to clone, sync, and clean the
repository.

### Native execution is the default

A native `fugue.yaml` with no explicit backend override launches native
Meerkat/Meta execution mobs. Fugue queues run from `fugue.yaml`.

### Evidence gates completion

Fugue reconciles Meta events, workspace state, Linear workpad content, and
GitHub pull request evidence. Missing or contradictory evidence sets review
requirements instead of silently completing an issue.

## Safe validation commands

These checks do not create live Linear, GitHub, or Meta resources:

```bash
cargo fmt --check
cargo test
cargo run -- --help
```

Do not run the ignored real E2E suite unless you have an operator-approved live
sandbox. It creates real external resources.
